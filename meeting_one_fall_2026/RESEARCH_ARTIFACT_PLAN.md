# Research artifact plan

The long-term goal is a QML Torch release that can be cited as software and used as a methods component in future papers. Citation is earned through usefulness, permanence, and clear credit; it is not an outcome we can guarantee.

## Release ladder

### Meeting 1 — executable method

- One fixed dataset and one classical control.
- One two-qubit hybrid layer.
- Forward pass, backward pass, and a saved run record.

### First team release — reusable tool

- Stable constructor and shape validation.
- Versioned examples and tests.
- Result serialization with configuration, seed, versions, and runtime.
- Methods note describing what the layer does and does not claim.

### Archived release — citable artifact

- Git tag and changelog.
- `CITATION.cff` with contributor roles.
- Permanent archive and DOI, created only after the release is reviewed.
- Reproduction instructions tested in a clean environment.
- A small figure and machine-readable data generated by the release.

## Claim discipline

Every result should be labeled as one of:

- **Implemented:** code exists and a test covers it.
- **Observed:** a specified run produced the recorded output.
- **Supported:** repeated clean runs and review justify the conclusion.

We will not describe QML Torch as hardware-ready, faster, or quantum-advantaged without evidence for that specific claim.

## Who receives credit

Credit follows the artifact: people who make substantial, documented, reviewed contributions appear in release notes and the citation metadata. Independent projects stay outside this repository and keep their own authorship and claims.

## Meeting 1 handoff

The pair's deliverable is a completed `submission.md`, a reviewable change to `starter_experiment.py`, and one issue that moves the tool toward the first team release. That is the first step toward a paper-quality artifact.
