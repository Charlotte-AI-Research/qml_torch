# 10-28-26

## What did you push?

Completed the nested `qml-torch` v0.1 tool end to end. The package now has a
working installation configuration, typed experiment settings, PennyLane backend
adapter, angle encoding, Pauli-Z measurements, a trainable PyTorch quantum layer,
data validation, classical/VQC training, guided CLI, circuit/report output, a
beginner example, and 19 automated tests.

The runnable path is:

```text
cd qml-torch
pip install -e ".[dev]"
qml-torch run examples/train.py
```

## What did this accomplish?

The five first-version tasks are now implemented. A user can provide a trusted
`train.py` with `get_data()`, choose qubits, model mode, encoding, shots, and
measurement, then receive a classical/hybrid comparison and saved `results.json`.
The v0.1 scope stays intentionally small: 2–6 qubits, angle encoding, Pauli-Z
expectations, equal feature/qubit counts, and binary classification.

## Any errors?

The classical and hybrid metrics are experimental comparisons and do not
demonstrate quantum advantage. The tool executes the user's training script as
trusted code. PennyLane's current device-level shot deprecation is avoided by
setting shots on the QNode.

The local verification completed with 19 passing tests and Ruff reporting no
errors. Root CI now also installs and checks the nested package.
The root pytest configuration was narrowed to the root `tests/` directory so the
two packages keep separate test environments.
